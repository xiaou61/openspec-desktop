## Context

参见 [proposal.md](./proposal.md) 的动机说明。当前渲染层由 `App.tsx` 组织三栏工作区，`lifecycle-view.tsx` 负责生命周期与就绪检查，约 2700 行的 `styles.css` 同时包含基础令牌、布局、组件、响应式和动效规则。

现有实现已经具备 120 至 240 毫秒的基础动效令牌、Radix 浮层状态、减少动态效果规则和部分玻璃层级，但视觉规则分散，生命周期轨道使用固定最小宽度，原生 `details` 展开会突然改变空间，通知卸载前没有独立退出阶段。此次只调整渲染层表现，不改变主进程计算出的生命周期事实，也不改变 IPC 或持久化契约。

`visualize-change-lifecycle-and-readiness` 仍处于实施中，因此实现必须以届时工作区的实际代码为准，保留其行为和未提交改动，并先完成一次针对重叠区域的差异核对。

## Goals / Non-Goals

**Goals:**

- 把视觉、布局、状态与动效令牌变成单一来源，减少局部任意值。
- 在不降低信息密度的情况下，让项目、Change、详情与生命周期形成明确扫描顺序。
- 让六类高价值状态变化具有一致、可中断且性能稳定的动效。
- 以容器实际空间驱动详情区域适配，并覆盖长内容、键盘和系统偏好降级。
- 让样式按职责可维护，同时控制本次重构的风险。

**Non-Goals:**

- 不改变 Change、任务、验证、归档规格影响或归档的业务状态机。
- 不增加暗色主题、用户自定义主题、Vercel 品牌复刻或营销式页面。
- 不引入通用动画引擎、全局状态库或新的组件框架。
- 不为所有元素添加动画，不制作循环背景、视差、闪烁、渐变流光或逐项列表编舞。
- 不在本变更中归档其他 OpenSpec Change。

## Decisions

### 1. 用语义令牌统一视觉与动效

建立原始颜色与尺寸、语义表面与文字、组件状态三层令牌。语义层至少覆盖画布、侧栏、内容、浮层、边界、主文字、次文字、焦点、成功、警告、错误和信息状态；组件不得直接复制近似色值。字号保持固定级别，不随视口连续缩放，字间距统一为零。

动效令牌按用途命名，而不是按组件命名：

| 用途             | 时长      | 缓动方向                      |
| ---------------- | --------- | ----------------------------- |
| 按压与选择       | 100-160ms | 快速响应、柔和结束            |
| 小型状态与展开   | 160-220ms | ease-out 或平衡的 ease-in-out |
| 通知与对话框进入 | 200-240ms | ease-out                      |
| 临时内容退出     | 120-160ms | 更快结束                      |

选择该方案是为了让新增组件自然获得一致表现。替代方案是继续在单个选择器内调整数值，但这会保留当前难以审计的漂移。

### 2. 渐进拆分样式，不一次性重写组件体系

`styles.css` 保持渲染入口，按稳定顺序导入令牌、工作区布局、通用组件、生命周期、动效与响应式文件。只迁移本次实际修改的规则，并在每批迁移后删除原位置定义，避免新旧选择器长期并存。

不改用 CSS Modules 或 CSS-in-JS，因为现有组件依赖全局类名与 Radix `data-state`，全量迁移会扩大风险且不会直接改善用户体验。也不采用全局 `transition: all`，每个组件只声明需要变化的属性。

### 3. 保留三栏骨架，重新分配密度与层级

桌面布局继续使用 CSS Grid，但将项目栏保持为稳定窄栏，Change 栏采用有界弹性宽度，详情栏获得剩余主要空间。标题区和列表行降低不必要的最小高度；项目和 Change 的选择态改为细选择轨、轻背景与清晰焦点，不继续模拟浮起卡片。

详情标题把名称、主要状态和辅助元数据分为两级：名称允许受限换行，状态只保留一个主要结论，版本与时间进入次要行。标签导航保持紧凑粘性层，不与大标题争夺高度。

选择保留三栏而不是改为路由式单页，是因为它对应“项目 → Change → 证据”的高频扫描路径。替代方案会增加来回导航成本，也会破坏用户当前的空间记忆。

### 4. 生命周期按详情容器自适应

详情区域建立 inline-size 容器，生命周期轨道根据自身可用宽度切换两种表现：宽布局显示完整节点标签与连接；紧凑布局保留提案、规格、设计、任务、验证、归档六个节点、短标签和可访问完整名称，同时缩短间距。归档规格影响保留在归档门槛内作为只读说明，不占用独立生命周期节点。节点使用等分网格与 `min-width: 0`，移除固定 `min-width` 和页面级横向滚动。

选择容器查询而不是只用视口媒体查询，是因为侧栏开关、Change 栏宽度和窗口宽度都可能改变详情的实际空间。若运行环境不支持容器查询，则以紧凑布局作为安全默认值。

### 5. 状态表达先归一化，再决定动画

建立统一的状态视觉映射，列表、详情标题与生命周期共享相同术语、图标和语义色。每个区域只展示完成其任务所需的状态强度：列表强调当前阶段与任务进度，详情标题强调总体结论，生命周期承担完整阶段证据。重复的“已完成 + 100% + 满进度条”等内容不再同时作为三个强视觉元素。

生命周期变化只过渡节点表面、图标和连接填充。连接通过不改变布局的比例变化表达前进，节点状态在原位置交叉淡入；任何节点都不会持续脉冲，只有真实运行中的验证图标允许循环。

### 6. 用受控披露替代突然跳变的原生详情

同步能力和检查证据使用可复用的披露组件：按钮维护 `aria-expanded`，正文使用具名区域关联，React 只管理开关状态，CSS 通过网格轨道与透明度完成 160 至 220 毫秒的可反向过渡。关闭内容在不可见后仍必须从键盘顺序中移除。

继续直接使用原生 `details` 虽然语义简单，但当前目标环境中难以可靠实现可中断的高度过渡；使用固定高度或读取 `scrollHeight` 则会产生内容截断或逐帧布局成本。受控披露提供更稳定的行为边界，同时保留标准按钮与区域语义。

### 7. 六类动效分别处理，不建立全局编舞

本次只实现以下动效：

1. 生命周期节点与连接的状态连续性。
2. 就绪检查和同步能力的展开收起。
3. 验证按钮在空闲、运行、成功和失败之间的稳定内容切换。
4. 通知在固定区域的进入与退出。
5. 窄屏项目侧栏与遮罩的同步进入退出。
6. 项目与 Change 选择轨、背景和按压反馈。

标签内容仅允许一次不超过 160 毫秒的轻透明度变化，键盘触发结果立即生效。实时活动列表不做全列表重播，行悬停不再上浮。以上约束来自“变化是否需要解释”的判断，而不是视觉丰富度。

### 8. 临时内容使用最小化的存在状态

通知与需要退出动画的临时层增加 `entering/open/closing` 存在状态；关闭时先进入 `closing`，在共享退出时长后卸载。新的通知到达时替换或合并当前状态，不排队播放过期动画。定时器集中清理，组件卸载后不得继续运行。

不引入 Framer Motion 或其他运行时库，因为当前动效数量有限，CSS 转换与少量存在状态足以覆盖需求，并能减少包体和主线程工作。

### 9. 降级规则是令牌的一部分

`prefers-reduced-motion: reduce` 不再依赖把所有时长强行设为极小值，而是将位移、缩放、网格展开和循环动画切换为即时状态，保留焦点、边界、图标与文字反馈。透明度降级继续使用不透明表面；高对比模式增强边界和焦点，不通过增加阴影补偿。

这样可以避免极小时长动画仍触发结束事件与存在状态定时器的边缘问题。替代方案是全局禁用所有 transition，但会丢失必要的颜色和焦点反馈。

## Risks / Trade-offs

- [生命周期功能仍在变化，样式与结构可能重叠] → 实施前重新读取该 Change 的最终组件结构，只在当前代码上增量修改，不回退已有工作。
- [拆分单体样式可能改变级联顺序] → 保持明确导入顺序，每次只迁移一个职责区并删除旧规则，使用支持窗口尺寸逐项核对。
- [紧凑轨道可能让标签过短] → 保留中文短标签、图标和完整可访问名称，宽布局仍展示完整文本。
- [展开动画涉及布局属性] → 只在用户主动展开的小型区域使用网格轨道，不对实时列表或整页高度做连续动画。
- [通知退出状态引入定时器] → 使用单一共享时长和集中清理；减少动态效果时直接卸载。
- [减少徽标可能让部分状态不够显眼] → 每个区域保留一个主要状态，并让完整证据始终能在生命周期或详情中定位。

## Migration Plan

1. 保存当前常用窗口与最小窗口的视觉基线，核对进行中的生命周期实现。
2. 建立视觉、状态与动效令牌，并完成受控的样式职责拆分。
3. 依次调整三栏骨架、列表、详情标题、标签和生命周期，不同时改动业务数据流。
4. 加入六类动效及减少动态效果、透明度和高对比降级。
5. 进行类型检查、针对性组件测试和桌面/窄窗口视觉核对；不运行会显著拖慢机器的完整 Electron 冒烟套件。
6. 重新打包桌面应用前复核长内容、键盘焦点和静止状态不存在循环装饰动画。

本变更无数据迁移。若视觉重构产生阻断性回归，可按职责回退对应样式与表现组件，不影响主进程数据和项目文件。

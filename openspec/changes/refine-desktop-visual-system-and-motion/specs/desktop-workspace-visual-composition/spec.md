## Purpose

为 OpenSpec 桌面工作区建立稳定、紧凑且可扫描的视觉编排规范，使项目、Change、生命周期和详情信息在不同窗口尺寸与内容长度下仍保持清晰层级，并让用户能够快速判断当前选择、进度与下一步。

## ADDED Requirements

### Requirement: 工作区必须具有统一的信息层级

系统 MUST 使用一致的标题尺度、正文字重、间距、边界、表面和控件尺寸区分应用导航、项目、Change、详情标题、主要内容与辅助元数据；紧凑面板内不得使用与页面主标题相同的夸张字号。

#### Scenario: 浏览包含多个层级的工作区

- **WHEN** 用户同时查看项目栏、Change 列表和详情面板
- **THEN** 当前项目、当前 Change、主要操作和辅助状态 MUST 具有可辨识但不过度重复的视觉优先级
- **THEN** 用户 MUST NOT 依赖阅读每个徽标才能判断当前选择和主要内容

#### Scenario: 查看详情标题

- **WHEN** Change 名称较长且详情标题同时包含状态、版本和时间
- **THEN** 标题与元数据 MUST 在可用宽度内换行或截断，并 MUST NOT 把标签导航或主要命令推出可视区域

### Requirement: 三栏主流程必须稳定且高效利用空间

系统 SHALL 保留项目、Change 与详情三栏主流程，并在常用桌面宽度下为列表扫描和详情阅读分配稳定空间；标题区、工具栏和列表行 MUST 使用与其信息量相称的高度。

#### Scenario: 使用常用桌面窗口

- **WHEN** 窗口宽度足以同时展示三栏
- **THEN** 三栏 MUST 同时可用，详情面板 MUST 获得主要阅读空间，且空白标题区域 MUST NOT 明显挤压正文高度

#### Scenario: 窗口接近应用声明的最小宽度

- **WHEN** 三栏无法在不遮挡内容的情况下同时展开
- **THEN** 项目导航 MUST 变为可明确打开和关闭的侧栏层级，Change 与详情区域 MUST 保持可操作
- **THEN** 页面 MUST NOT 出现由固定栏宽导致的整体水平滚动

### Requirement: 列表必须兼顾密度与状态识别

项目行和 Change 行 MUST 使用稳定的对齐、有限的元数据层级和明确的选择标记；状态、任务计数、进度与时间不得通过多组表达同一事实的徽标造成噪声。

#### Scenario: 快速扫描 Change 列表

- **WHEN** 列表包含不同进度和状态的多个 Change
- **THEN** 每行 MUST 以一致顺序呈现名称、主要状态、任务进度和更新时间
- **THEN** 选择状态 MUST 同时通过形状、边界或位置表达，而不是只改变背景颜色

#### Scenario: 同一事实存在多个标签候选

- **WHEN** “任务已完成”和“100% 进度”等信息表达同一进度事实
- **THEN** 界面 MUST 选择一个主要表达并将其余内容降为辅助信息或省略

### Requirement: 生命周期必须在可用宽度内保持连续可读

生命周期轨道 MUST 保留提案、规格、设计、任务、验证和归档的顺序与状态关系，并在详情面板可用宽度不足时采用紧凑标签、分段换行或其他不丢失节点的自适应布局；规格影响 MUST 作为归档门槛内的只读说明呈现，而不是独立生命周期节点。

#### Scenario: 标准详情宽度

- **WHEN** 详情面板能容纳完整生命周期轨道
- **THEN** 所有节点、连接关系、当前状态和可用操作 MUST 在一个连续视图中清晰呈现

#### Scenario: 详情面板宽度不足

- **WHEN** 完整节点标签无法在一行内显示
- **THEN** 轨道 MUST 自适应为紧凑布局且 MUST NOT 依赖页面级横向滚动条才能理解完整流程
- **THEN** 每个节点的完整名称与状态 MUST 仍能通过可见文字或可访问名称获取

### Requirement: 状态必须使用一致且克制的语义表达

系统 MUST 为成功、进行中、等待、警告、错误、不可用和已归档使用统一的文字、图标、形状与颜色语义；颜色 MUST NOT 是唯一信息载体，普通状态不得与主要操作竞争注意力。

#### Scenario: 查看生命周期与列表状态

- **WHEN** 同一 Change 的状态同时出现在列表、标题和生命周期中
- **THEN** 相同状态 MUST 使用一致术语和语义样式
- **THEN** 重复位置 MUST 根据上下文简化内容，而不是堆叠相同强度的徽标

#### Scenario: 出现警告或错误

- **WHEN** 验证失败、状态未知或存在阻塞
- **THEN** 界面 MUST 使用图标或文字明确说明结果，并使诊断或下一步可定位

### Requirement: 内容表面必须建立清晰而克制的层级

系统 SHALL 将半透明与背景模糊限制在导航、粘性工具栏、菜单、通知和对话框等需要表达前后层级的位置；密集列表、Markdown 正文和检查证据 MUST 使用稳定的高可读基底，且页面区域不得被逐层包装为嵌套卡片。

#### Scenario: 查看密集详情内容

- **WHEN** 用户浏览长文档、活动、修订或归档规格影响
- **THEN** 正文与表格 MUST 保持清晰对比，边界与表面 MUST 帮助分组而不是制造多层浮动卡片

#### Scenario: 透明效果不可用

- **WHEN** 系统不支持背景模糊或用户要求减少透明度
- **THEN** 相关表面 MUST 使用实色、边界和阴影降级，并保持同等信息层级与文字可读性

### Requirement: 所有内容状态必须保持稳定与可访问

系统 MUST 为默认、悬停、按下、键盘焦点、选中、禁用、加载、空、成功和错误状态提供明确表现；状态切换不得造成控件尺寸变化、文字遮挡或焦点丢失。

#### Scenario: 仅使用键盘操作工作区

- **WHEN** 用户使用 Tab、Shift+Tab、方向键、Enter、Space 和 Escape 浏览及操作
- **THEN** 焦点顺序、可见焦点、控件名称和关闭后的焦点返回 MUST 与视觉层级一致

#### Scenario: 内容包含长中文、路径或连续字符

- **WHEN** 项目名、Change 名称、能力名或文件路径超过容器宽度
- **THEN** 内容 MUST 安全换行或截断且 MUST 提供完整值，不得覆盖相邻文字、图标或操作控件

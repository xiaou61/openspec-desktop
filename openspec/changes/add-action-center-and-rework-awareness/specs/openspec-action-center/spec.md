## Purpose

为所有已登记的本地 OpenSpec 项目提供一个可追溯的行动中心，把分散在各个 Change 中的下一步、阻塞、环境健康和 Codex 交接内容汇总为可安全执行的工作队列。

## ADDED Requirements

### Requirement: 行动中心必须汇总所有已登记项目中可执行的下一步

系统 MUST 为每个已登记项目中的每个可读取 Change 派生至多一个主要行动，并在应用级行动中心以确定顺序汇总所属项目、所属 Change、行动摘要、状态证据和跳转目标。行动中心 MUST 支持查看全部项目或聚焦当前项目，并 MUST 覆盖恢复项目或 OpenSpec 环境、补充或解除工件阻塞、继续实施未完成任务、重新运行严格验证、等待用户确认归档以及检查归档内容异常等可操作状态。没有可操作项时，系统 MUST 明确显示当前范围没有待处理行动，而不是把空白误表示为未知或成功。

#### Scenario: 多个项目的 Change 处于不同阶段

- **WHEN** 多个已登记项目中同时存在工件缺失、任务未完成、验证过期和可归档的 Change
- **THEN** 行动中心 MUST 为每个 Change 显示所属项目、主要行动及形成该结论的证据
- **THEN** 行动中心 MUST 按项目不可用或环境问题、工件阻塞、实施任务、验证、归档确认和信息性异常的优先级稳定排序，并以项目身份和 Change ID 稳定打破同级排序

#### Scenario: 任务未完成的 Change

- **WHEN** 一个当前 Change 的任务门槛显示已完成 57 项、总计 64 项
- **THEN** 行动中心 MUST 将“继续实施剩余 7 项任务”作为该 Change 的主要行动
- **THEN** 行动项 MUST 能导航回该 Change 及其任务或就绪证据

#### Scenario: 当前范围没有待处理行动

- **WHEN** 当前选择的全部项目或单个项目范围内所有可读取 Change 均已归档且不存在环境问题或归档异常
- **THEN** 行动中心 MUST 显示当前范围没有待处理行动
- **THEN** 系统 MUST NOT 凭空生成实施、验证或归档操作

### Requirement: 行动结论必须展示 OpenSpec 证据与降级状态

系统 MUST 按各已登记项目根分别使用本机 OpenSpec CLI 的结构化 `status`、`instructions`、`doctor` 和 `context` 结果形成行动证据，并标明每条结论的来源、检查时间和适用根目录。某一项目的 CLI 调用缺失、不兼容、超时或返回不可解析结果时，系统 MUST 保留该项目可从本地结构扫描得到的浏览和任务行动，但 MUST 显示降级原因，且 MUST NOT 把推测的 schema、条件工件或健康结论显示为 CLI 权威结果或影响其他健康项目的结论。

#### Scenario: CLI 可用且报告工件阻塞

- **WHEN** OpenSpec CLI 报告一个 Change 的下一个工件及其缺失依赖
- **THEN** 行动中心 MUST 显示该工件、依赖和 CLI 作为证据来源
- **THEN** 行动项 MUST 不把尚未完成的依赖显示为可完成或已完成

#### Scenario: CLI 不可用

- **WHEN** 本机无法执行兼容的 OpenSpec CLI
- **THEN** 行动中心 MUST 显示环境健康问题和恢复提示
- **THEN** 已能由本地扫描确认的 Change、文档和未完成任务 MUST 继续可见，并明确标为结构降级结论

### Requirement: 行动中心必须生成受限的 Codex 交接内容

系统 MUST 为可交给 Codex 的行动生成可复制或可打开的交接内容，其中包含已验证的项目根、Change 身份、行动类型、当前证据、已知阻塞和适用的 OpenSpec 工作上下文。交接内容 MUST 区分“规划工件尚未完成”“继续实施任务”“重新严格验证”和“等待用户确认归档”等行动，不得把只读检查结论改写为代码已经交付或验证通过。

#### Scenario: 用户交接未完成任务

- **WHEN** 用户从行动中心选择一个具有未完成任务的 Change 的 Codex 交接
- **THEN** 系统 MUST 生成包含项目根、Change ID、完成数、总数、剩余数和继续实施指令的内容
- **THEN** 交接内容 MUST 保留该 Change 的实际任务文件或 OpenSpec 上下文入口

#### Scenario: 用户交接环境问题

- **WHEN** 用户选择 CLI 不可用或 OpenSpec 健康异常的行动交接
- **THEN** 系统 MUST 生成包含已观察诊断和项目根的排查内容
- **THEN** 系统 MUST NOT 在生成交接内容时执行命令、修改项目文件或暴露不受限的进程输出

### Requirement: 行动中心必须保持本地只读和可追溯边界

行动中心及其 Codex 交接 MUST 只读取经验证项目根中的 OpenSpec 状态和应用本地数据。系统 MUST NOT 因刷新行动、复制交接内容、打开 Change 或查看健康状态而创建 OpenSpec 工件、勾选任务、执行归档、修改 Git 或上传项目路径和内容。每个行动 MUST 提供可访问名称、非颜色状态文本和返回对应证据的路径。

#### Scenario: 用户刷新全部项目行动中心

- **WHEN** 用户刷新项目行动中心
- **THEN** 系统 MUST 分别重新读取当前范围内每个项目允许的本地状态并更新行动与证据新鲜度
- **THEN** 所有项目目录、任务勾选、Change 目录位置和主规格内容 MUST 保持不变

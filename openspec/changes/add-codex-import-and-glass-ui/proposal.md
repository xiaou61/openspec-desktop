## 为什么

当前只能通过目录选择器逐个添加项目，个人在 Codex 中切换多个本地项目时，需要重复定位目录，无法快速把已经工作的项目纳入 OpenSpec 进度面板。同时现有界面虽然功能完整，但视觉层级和交互精度不足以支撑长期、高频的桌面使用。

## 变更内容

- 增加“从本机 Codex 导入”入口，从 Codex 桌面端维护的本地项目索引中发现曾使用过的项目目录。
- 仅提取项目名称、根目录、排序和更新时间，不导入对话正文、账号信息、令牌或其他隐私数据。
- 对候选目录执行路径去重、可访问性检查和 OpenSpec 项目校验，并标明已导入、不可用等状态。
- 提供刷新、全选/取消全选、多选和批量导入，导入后立即进入现有监控与进度投影流程。
- 重新设计桌面工作区，采用 Vercel 风格的黑白高对比、紧凑控件和清晰边界，并在导航、工具栏和弹窗层级加入克制的 iOS 玻璃质感。
- 完善窗口缩放、长文本、键盘焦点、减少动态效果以及不支持背景模糊环境下的降级表现。
- 本次 OpenSpec 提案、规格、设计和任务说明使用中文；协议规定的机器可读关键字除外。

## 能力

### 新增能力

- `codex-project-import`：从本机 Codex 项目索引发现、筛选并批量导入有效 OpenSpec 项目。
- `glass-desktop-interface`：为桌面工作区提供 Vercel 式组件语言、iOS 玻璃层级、响应式布局和无障碍交互。

### 修改能力

无。本仓库当前没有已归档到 `openspec/specs/` 的主规格；本次以两个独立新增能力描述行为增量。

## 影响范围

- Electron 主进程：Codex 数据目录定位、本地项目索引读取、候选项目校验和批量注册。
- IPC 与 preload：新增最小化、类型安全的候选查询和批量导入接口，渲染进程不直接获得任意文件读取权限。
- React 渲染进程：新增 Codex 导入弹窗及其空态、加载态、错误态和选择状态。
- 视觉系统：调整设计令牌、基础组件和三栏工作区样式，但保留现有信息架构、文件监控和本地持久化语义。
- 测试与分发：补充主进程和 UI 流程验证，重新生成 Windows 安装包与便携版，并在验证完成后创建 GitHub 私有仓库进行首次推送。

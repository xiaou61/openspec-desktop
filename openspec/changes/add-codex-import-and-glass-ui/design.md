## 背景

当前应用是 Electron、React 与 TypeScript 构建的本地只读 OpenSpec 监控器。项目注册由主进程控制器统一完成，渲染进程通过类型化 preload API 调用；目录合法性检查、扫描、文件监控和目录持久化已经存在。现有 UI 为三栏工作区，使用 Radix Dialog、Dropdown Menu、Tabs 和 Lucide 图标，但样式主要集中在单个页面和样式表中。

Codex 桌面端在 `CODEX_HOME` 或用户目录下的 `.codex/.codex-global-state.json` 中维护本地项目和已保存工作区索引。项目索引可以直接提供名称、多个根目录、顺序和更新时间，不必遍历会话正文。该文件仍包含其他本机敏感状态，导入功能必须维持现有 Electron 权限边界。需求动机见 `proposal.md`，可观察行为见两份能力规格。

## 目标与非目标

**目标：**

- 复用现有项目注册、扫描和监控流程，仅新增安全、有限的 Codex 候选发现层。
- 让用户从一个入口选择“浏览文件夹”或“从 Codex 导入”，并能在模态界面中批量处理候选。
- 建立可复用的视觉令牌和基础组件状态，使当前工作区与新导入界面采用同一设计语言。
- 保持 Windows 桌面应用在 920 像素最小宽度附近仍可操作，并为玻璃效果提供实色降级。

**非目标：**

- 不导入、展示、搜索或同步 Codex 对话内容。
- 不修改 Codex 数据，不持续监听 Codex 会话目录，也不把本机元数据上传到网络。
- 不引入账户、云同步、多人协作或 GitHub 登录功能。
- 不改变 OpenSpec 文件的只读监控语义，也不在本次变更中重写扫描器或历史存储。
- 不逐像素复制 Vercel 或 iOS；仅借鉴组件密度、对比、边界和材质层级。

## 技术决策

### 1. 在主进程增加独立的 Codex 候选发现服务

新增无 UI 依赖的领域服务，输入 Codex 根目录、已注册项目路径与扫描限制，输出经过结构化校验的候选列表和扫描摘要。控制器负责调用服务并复用现有单项目注册能力完成批量导入。

选择该方案是因为文件系统和用户目录只能由主进程访问，且独立服务便于对临时目录和损坏 JSONL 做确定性测试。备选方案是让渲染进程直接读取文件或把整个会话文件通过 IPC 传回；这会扩大权限和隐私暴露面，因此不采用。

### 2. 以全局状态中的项目索引作为唯一首版数据源

根目录解析顺序为有效 `CODEX_HOME` 优先，否则使用 Electron 提供的当前用户目录拼接 `.codex`。服务读取标准 `.codex-global-state.json`，以宽松结构只挑选 `local-projects`、`project-order` 和 `electron-saved-workspace-roots`；项目 ID 视为不透明字符串，`rootPaths` 保持多根语义，未知字段全部忽略。

标准文件疑似处于并发写入状态时进行有限短重试，仍失败后只读尝试 `.codex-global-state.json.bak`，不读取任何带临时后缀的写入文件。设置状态文件字节上限和候选根目录数量上限，响应用 `source` 与 `truncated` 标识备份降级和截断。

候选先按照 `project-order` 中的本地项目顺序展开多根目录，再追加未覆盖的已保存工作区。候选以平台规范化后的绝对路径作为去重键；Windows 去除 `\\?\` 扩展路径前缀，比较时忽略大小写和尾部分隔符。最近使用时间取项目合法的 `updatedAt`，仅保存工作区没有时间时保持为空。

备选方案包括扫描 `sessions`/`archived_sessions` 首行、查询 `state_5.sqlite` 或调用 Codex CLI。会话首行还含基础指令，SQLite 同表含消息预览且正确处理 WAL 需要额外复杂度，CLI 则有进程启动和版本差异；首版均不采用，从源头减少隐私接触面。

### 3. IPC 只暴露经过 Zod 校验的最小数据

共享契约增加候选状态、候选列表结果、列表请求和批量导入请求。IPC 增加“列出 Codex 项目”和“导入 Codex 项目”两个通道，preload 仅暴露对应方法。候选对象只包含稳定 ID、显示名称、根路径、最近使用时间、可选状态和中文原因，不包含原始会话路径或原始 JSON。

批量导入请求只接受本次候选中的规范化项目根路径，并在真正注册前重新校验，避免候选展示与确认之间的目录状态变化。响应返回最新应用快照和逐项结果，使部分成功可以准确反馈。

### 4. 复用注册流程并明确部分成功语义

控制器抽出或复用不依赖目录选择器的单项目注册路径。批量操作串行处理选中目录，避免同时创建多个监控器时产生竞争；每个成功项立即进入目录存储、初始扫描和 watcher 启动，失败项记录错误但不回滚其他成功项。

备选方案是事务式全部成功或全部失败，但文件系统状态可能在处理期间变化，而且已启动的 watcher 回滚复杂，个人导入场景下保留成功结果更实用。

### 5. 添加项目入口使用菜单，Codex 导入使用 Radix Dialog

侧边栏加号继续作为唯一主入口，点击后显示紧凑菜单，提供“选择文件夹”和“从 Codex 导入”。Codex 导入弹窗使用现有 Radix Dialog 的焦点锁定、Escape 关闭和可访问标题能力；候选列表使用原生复选框语义配合自定义外观，底部操作区固定显示已选数量与确认按钮。

数据获取沿用 React Query：打开时请求候选，刷新使查询失效，确认导入使用 mutation。成功后以返回快照更新工作区，保留失败项并展示逐项信息；全部成功后关闭弹窗并选中最近成功导入的项目。

### 6. 以 CSS 设计令牌和浅层基础组件完成视觉升级

不新增大型组件库。继续使用现有 Radix 行为原语与 Lucide 图标，在渲染层整理按钮、图标按钮、徽标、分段控件、列表行、输入框、菜单和弹窗的共享 class 与状态。根级 CSS 变量覆盖颜色、边框、层级背景、阴影、圆角、控件高度、间距和过渡时长。

视觉基准采用中性黑白与少量语义绿、黄、红：内容面使用不透明背景，侧边栏、粘性工具栏、菜单和模态使用带 `backdrop-filter` 的半透明表面。通过 `@supports` 提供实色降级，通过 `prefers-reduced-motion` 关闭非必要过渡。圆角默认 6 到 8 像素，避免大面积胶囊、装饰渐变和光球。

### 7. 保留三栏信息架构并收紧响应式约束

主工作区继续使用明确的三列网格，给侧栏、列表和详情设置稳定的最小/最大轨道；图标按钮、状态点、进度条和工具栏使用固定尺寸，动态内容不得改变控件几何。接近最小窗口宽度时收紧非关键间距和侧栏宽度，路径与名称使用 `min-width: 0`、换行或省略，并用 `title` 或 Tooltip 提供完整值。

备选方案是改成卡片式仪表盘或移动端抽屉，这会降低桌面高频扫描效率，也不符合现有工作流，因此不采用。

## 风险与取舍

- **Codex 全局状态属于内部格式**：解析器对未知字段宽容，不假定项目 ID 格式，并用字段缺失与损坏样本验证降级行为。
- **全局状态并发写入或项目很多**：有限重试后回退备份，设置文件字节和候选数量上限，并在 UI 中标识降级与截断。
- **项目名称和绝对路径属于本机隐私**：数据只在本机主进程、受控 IPC 和可见导入界面之间流转，不读取认证文件、会话正文或 SQLite 消息列，也不引入网络请求。
- **玻璃效果降低对比或消耗 GPU**：只用于少量层级，正文面保持实色，并提供 `@supports` 和减少动态效果降级。
- **大范围 CSS 调整造成回归**：保持组件结构和语义不变，分阶段迁移令牌、框架、列表、详情和弹窗，并用固定桌面视口截图检查重叠和可读性。
- **首次推送可能误含本机构建产物**：推送前核对 `.gitignore`、待提交文件和仓库可见性；默认创建私有仓库，只提交源代码与必要配置。

## 迁移与发布

1. 先增加共享契约、发现服务和 IPC，并保持旧的文件夹添加流程可用。
2. 再接入 Codex 导入界面，完成成功、空、损坏、截断和部分失败路径。
3. 分层替换视觉令牌与样式，保留现有功能组件和数据流。
4. 运行类型检查、lint、单元测试、构建、浏览器 UI 流程和 Electron UI 流程；在桌面与最小窗口视口检查截图。
5. 重新生成 Windows 安装版和便携版，记录产物名称、大小和 SHA-256。
6. 初始化 Git，检查提交内容后创建 GitHub 私有仓库并推送默认分支。

如需回滚，Codex 导入入口、IPC 和发现服务可一并移除，原有目录选择添加方式不受数据迁移影响；视觉层可以恢复原令牌与样式文件，项目目录和历史数据格式均无需回滚。

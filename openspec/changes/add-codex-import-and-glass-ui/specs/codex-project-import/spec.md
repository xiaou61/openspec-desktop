## Purpose

让个人用户能够从本机 Codex 维护的项目索引中发现有效 OpenSpec 项目，并在不使用或泄露对话正文及凭据的前提下快速批量加入桌面监控工作区。

## ADDED Requirements

### Requirement: 定位本机 Codex 数据

系统 SHALL 优先使用明确配置的 Codex 数据目录，并在未配置时使用当前用户目录下的标准 `.codex` 位置查找全局状态文件。

#### Scenario: 使用自定义 Codex 目录

- **WHEN** 当前进程存在有效的 `CODEX_HOME` 配置
- **THEN** 系统仅从该目录查找可用于项目发现的全局状态文件

#### Scenario: 使用默认 Codex 目录

- **WHEN** 当前进程未配置 `CODEX_HOME`
- **THEN** 系统从当前用户目录下的 `.codex` 目录查找全局状态文件

#### Scenario: Codex 数据不可用

- **WHEN** 目标 Codex 数据目录不存在、不可读或没有可识别的项目索引
- **THEN** 系统返回可恢复的中文空态或错误说明，且现有项目目录保持不变

### Requirement: 仅使用 Codex 项目索引字段

系统 MUST 仅使用全局状态中的 `local-projects`、`project-order` 和 `electron-saved-workspace-roots` 项目字段，不得向渲染进程返回或写入提示词历史、排队消息、线程内容、账号数据、令牌或其他无关字段。

#### Scenario: 发现本地项目根目录

- **WHEN** `local-projects` 中的项目包含一个或多个 `rootPaths`
- **THEN** 系统保留项目名称、顺序和更新时间，并将每个规范化根目录作为独立候选进行校验

#### Scenario: 全局状态包含敏感字段

- **WHEN** 同一全局状态文件还包含提示词历史、权限或其他与项目索引无关的数据
- **THEN** 系统忽略这些数据，候选结果仅包含导入界面所需的项目名称、规范化路径、最近使用时间和状态

#### Scenario: 补充已保存工作区

- **WHEN** `electron-saved-workspace-roots` 包含未被 `local-projects` 覆盖的根目录
- **THEN** 系统使用目录名称作为显示名称并将其追加为候选，不遗漏 Codex 已保存的独立工作区

### Requirement: 安全读取 Codex 全局状态

系统 SHALL 优先读取标准 `.codex-global-state.json`，对文件大小和候选根目录数量设置固定上限，并在疑似并发写入导致解析失败时进行有限重试，再只读回退到 `.bak` 文件；系统 MUST 忽略临时写入文件。

#### Scenario: 标准状态文件有效

- **WHEN** 标准全局状态文件存在且包含可识别的项目字段
- **THEN** 系统使用标准文件生成候选，不读取备份或临时文件

#### Scenario: 状态文件正在写入

- **WHEN** 标准文件在读取期间变化或暂时无法解析
- **THEN** 系统进行有限次数的短暂重试，仍失败时只读尝试对应 `.bak` 文件并返回降级来源提示

#### Scenario: 仅存在临时写入文件

- **WHEN** 数据目录只存在名称带临时后缀的全局状态文件
- **THEN** 系统忽略临时文件并返回可恢复的中文空态或错误说明

### Requirement: 确定地排序并去重候选

系统 SHALL 遵循 `project-order` 展示本地项目，将仅存在于已保存工作区的路径追加在后，并以平台规范化绝对路径对所有根目录去重。

#### Scenario: 多个索引项指向同一项目

- **WHEN** 多个项目或已保存工作区指向规范化后相同的工作目录
- **THEN** 系统只返回一个候选，并优先保留本地项目的名称、排序和更新时间

#### Scenario: 根目录数量超过上限

- **WHEN** 可用项目根目录数量超过系统设定的候选上限
- **THEN** 系统按确定顺序保留有限数量的候选，并返回已截断提示而不是无限处理

#### Scenario: Windows 扩展路径与普通路径重复

- **WHEN** `\\?\C:\\项目` 与 `C:\\项目` 指向同一 Windows 目录
- **THEN** 系统移除扩展路径前缀、忽略大小写与尾部分隔符后只保留一个候选

### Requirement: 校验并标记导入资格

系统 SHALL 在展示候选前检查目录是否存在、是否可读、是否包含可识别的 `openspec` 结构，并与当前项目目录进行路径级去重。

#### Scenario: 有效的新项目

- **WHEN** 候选目录可读、包含有效 OpenSpec 结构且尚未注册
- **THEN** 系统将其标记为可选择并默认允许用户导入

#### Scenario: 项目已经导入

- **WHEN** 候选目录与目录中已有项目的规范化路径相同
- **THEN** 系统将其标记为“已添加”并禁止重复选择

#### Scenario: 候选目录不可导入

- **WHEN** 候选目录不存在、不可读或不包含有效 OpenSpec 结构
- **THEN** 系统展示对应中文原因并禁止选择该候选

### Requirement: 交互式刷新与批量选择

系统 SHALL 提供从 Codex 导入的独立界面，支持加载、空态、错误、刷新、单项选择、全选可用项和取消全选。

#### Scenario: 打开导入界面

- **WHEN** 用户从添加项目入口选择“从 Codex 导入”
- **THEN** 系统打开可关闭的模态界面并自动加载最新候选列表

#### Scenario: 全选候选

- **WHEN** 用户触发全选且列表同时包含可用与不可用候选
- **THEN** 系统仅选择尚未导入的有效候选，并准确显示选中数量

#### Scenario: 刷新候选

- **WHEN** 用户在 Codex 新添加或打开项目后触发刷新
- **THEN** 系统重新读取本机项目索引并以最新结果替换当前候选列表

### Requirement: 批量导入保持现有项目语义

系统 SHALL 将选中的候选逐个注册到现有本地项目目录，并立即启动现有 OpenSpec 扫描、文件监控和进度投影；一个候选失败不得回滚已经成功导入的其他候选。

#### Scenario: 批量导入成功

- **WHEN** 用户确认导入一个或多个有效候选
- **THEN** 系统将每个项目加入目录、启动监控、刷新工作区，并报告成功数量

#### Scenario: 部分候选在确认后失效

- **WHEN** 批量导入期间某个候选目录被删除或变为不可读
- **THEN** 系统保留其他成功项目，并在导入界面中提供该候选的中文失败原因

#### Scenario: 未选择任何候选

- **WHEN** 当前选择数量为零
- **THEN** 系统禁用确认导入命令，且不修改项目目录

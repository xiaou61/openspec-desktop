## Why

当前公开 GitHub 仓库仍停留在旧提交，本机已经完成的多轮产品改动尚未形成一份经过清理、验证且可追溯的源码版本；现有 README 同时承担产品介绍、开发说明和零散使用说明，也不足以让首次使用者独立完成安装、项目接入与 Change 全流程操作。现在需要把当前可用版本安全发布到既有仓库，并提供一份与真实界面一致的中文操作手册。

## What Changes

- 审计当前 `main` 的已跟踪和未跟踪内容，明确源码、OpenSpec 变更文档、测试夹具与生成产物的发布边界。
- 排除 `.tmp-wmi-diagnosis/`、`output/` 等本机诊断或测试产物，并检查凭据、隐私路径、大文件和不应公开的配置，禁止未经审计直接全量暂存。
- 在 `docs/user-manual.md` 新增面向最终使用者的中文操作手册，覆盖安装与启动、首次使用、项目/工作区接入、Change 生命周期、任务与再次实施、严格验证、归档、历史、设置、数据安全和常见故障。
- 使用当前版本的真实界面截图说明关键流程；截图不得包含用户隐私、凭据或无关本机信息，并须在桌面端 Markdown/GitHub 页面可正常显示。
- 精简并校正 README 的使用入口，将完整步骤链接到操作手册，同时保留开发、构建和隐私边界说明。
- 对待发布源码运行项目既有的类型检查、静态检查、测试、边界检查和构建验证，记录任何未运行项及原因。
- 将审核后的相关改动形成清晰提交并推送至现有公开仓库 `https://github.com/xiaou61/openspec-desktop` 的 `main`，随后从 GitHub 端核对提交、手册链接与图片资源可访问。
- 本 Change 不创建 GitHub Release、版本标签、安装包附件、自动发布流水线，也不增加软件内置帮助页面。

## Capabilities

### New Capabilities

无。本 Change 只涉及源码交付与使用文档，不引入新的产品行为。

### Modified Capabilities

无。现有产品 Requirement 不发生变化，因此本 Change 使用 `skip_specs: true`，不创建长期能力规格。

## Impact

- 文档：`README.md`、`docs/user-manual.md` 及其脱敏截图资源。
- 仓库卫生：`.gitignore` 和确有必要的发布边界说明；不保留本机诊断、测试输出或秘密信息。
- 验证：沿用现有 `package.json` 脚本与 OpenSpec 严格验证，不新增运行时依赖或产品 API。
- 外部系统：既有公开 GitHub 仓库及其 `main` 分支；不改变仓库可见性、分支策略或 Release 配置。

## Context（背景）

参见 `proposal.md` 的 Why。当前目录把 `ProjectRecord.versionLabel` 作为唯一版本字段，注册和 Codex 导入默认写入空字符串；`WatcherManager.handleProjection` 闭包捕获启动时的 `ProjectRecord`，随后项目设置虽然更新目录数据，却不会更新该闭包。`HistoryStore` 已经在每条活动和修订上保存 `projectVersion` 与可选 `changeId`，但列表只把版本作为每行尾部文本展示，没有聚合或筛选。

目录文件使用严格 Zod schema；当前加载遇到任何 schema 不匹配都会把文件移为损坏备份并创建空目录。因此版本模型升级必须提供显式迁移，不能仅给严格对象增加必填字段。渲染进程继续受 Electron preload 边界约束，版本探测只能在主进程中完成。

现有依赖已经包含 Radix Dialog、Dropdown Menu、Tabs、Lucide 与 Tailwind；本次不需要新增动效库。UI 保持面向桌面高频工作的三栏密集布局，不改造成营销页面或大卡片仪表盘。

## Goals / Non-Goals（目标与非目标）

**Goals（目标）：**

- 建立可迁移、可解释且可更新的项目版本上下文，并让写入时版本可靠进入活动与修订。
- 利用已有 `projectVersion` 与 `changeId` 推导版本摘要和 Change 关联，避免维护第二套容易漂移的关系数据库。
- 让版本在导航、标题、Change、活动和修订中的信息层级一致，消除重复空值文案。
- 通过共享 CSS 动效令牌和 Radix 状态属性提供快速、可中断、可降级的界面反馈。

**Non-Goals（非目标）：**

- 不创建、切换或修改 Git 标签、分支、提交和远端 Release。
- 不实现语义化版本递增、发布编排、自动提交或包发布。
- 不把 Git 分支名伪装成版本；分支未来可作为独立开发上下文显示。
- 不回填猜测既有空版本历史；旧记录保持“当前工作区”归属。
- 不引入 Framer Motion、全局状态库或数据库。

## Decisions（设计决策）

### 1. 保留 `versionLabel` 作为有效快照值，增加来源元数据

`ProjectRecord.versionLabel` 继续表示当前有效标签并直接用于历史快照：真实版本保存原标签，无版本保存空字符串。项目目录新增：

- `versionMode: 'automatic' | 'manual'`
- `versionSource: 'git-tag' | 'package-json' | 'manual' | 'workspace'`
- `versionResolvedAt?: string`

界面把空标签映射为“当前工作区”，历史聚合使用稳定内部键 `workspace`，但不会把展示文案写回数据。所有非空真实标签使用 `version:<标签>` 作为查询键，因此字面标签 `workspace` 也不会与空版本历史冲突。保留字符串字段可避免迁移历史索引，也让现有记录与 API 的含义继续成立。

备选方案是创建独立 Version 实体和版本主键。当前版本关系完全可以从不可变历史快照推导，独立实体会引入删除、重命名和同步语义，超出个人本地工具所需，因此不采用。

### 2. 使用显式目录 v1→v2 迁移

`CatalogStore.load` 在严格解析前识别 schema 版本并执行纯数据迁移：

- 既有非空 `versionLabel` → `manual/manual`
- 既有空 `versionLabel` → `automatic/workspace`
- 项目、分组、顺序、监听状态、偏好和窗口尺寸原样保留

首次成功迁移前写入一个明确命名的 v1 备份，随后通过现有临时文件、刷新磁盘和原子替换流程保存 v2。迁移失败必须返回恢复信息，不能走“全部清空”的普通损坏恢复路径。历史索引 schema 不变。

备选方案是让新增字段可选并长期使用默认值。这样每个消费者都需要处理半迁移状态，也无法区分旧非空值是否应被自动覆盖，因此不采用。

### 3. 主进程提供有界的只读版本解析器

新增独立 `project-version-resolver` 模块，输入经过验证的项目根目录，输出候选上下文：

1. 使用 `execFile`（禁止 shell）在项目根目录运行 `git tag --points-at HEAD --sort=-version:refname`，设置超时、输出上限和隐藏窗口；选择第一个合法短标签。
2. Git 无结果或失败时，仅用 JSON 解析器读取根目录 `package.json`，限制文件大小并校验 `version` 为非空且不超过 120 字符。
3. 两者均无结果时返回空标签与 `workspace` 来源。

解析器不抛出可预期的 Git/文件缺失错误，而是在结果中提供安全的诊断代码供 UI 说明；不得回传命令原始 stderr 或任意文件内容。它不读取 Git 远端、不运行项目脚本、不访问网络。

备选方案是引入 Git 库。当前只需一个只读命令，新增大型依赖会扩大安装包和攻击面，不采用。

### 4. 自动刷新由应用生命周期事件驱动

应用初始化时只刷新迁移后处于自动模式的项目；注册、Codex 导入、重新定位、重新扫描、切回自动模式和版本菜单中的刷新命令复用同一协调函数。不会监听整个 `.git` 目录，也不会轮询；这避免额外文件监听成本和 Git 工具写入期间的抖动。

解析结果只有在有效标签、模式或来源变化时才创建项目设置活动；仅 `versionResolvedAt` 变化时静默持久化。手动模式的普通扫描直接跳过解析。

备选方案是实时监听 `.git/HEAD`、refs 和 `package.json`。Git 的 loose refs、packed refs 与工作树布局差异会显著增加复杂度，而用户已有“重新扫描”和显式刷新入口，因此首版不采用。

### 5. WatcherManager 持有可替换的最新项目上下文

`WatcherManager` 增加按项目 ID 保存的当前上下文和 `updateProjectContext(project)`。`handleProjection` 在准备每个 `RecordRevisionInput` 时读取映射中的最新 `versionLabel`，不再依赖启动闭包中的对象。`AppController` 在版本保存成功、向渲染进程返回前同步更新该上下文。

这种方式不重启 Chokidar，不产生监听空窗，也不会因重新初扫制造多余历史。暂停、移除项目时清理映射；重新启动时以目录记录初始化。

备选方案是在每次版本变化后停止并重启监听器。虽然内容哈希能抑制多数重复修订，但会产生监听空窗和不必要 I/O，因此不采用。

### 6. 历史存储按现有快照推导版本摘要

新增 `VersionSummary` 契约与只读查询：

- `key`、展示标签、是否当前版本
- 活动数、修订数、首次/最近时间
- 去重后的 `changeIds`

`HistoryStore` 从内存索引聚合，无需增加持久化索引。活动和修订列表请求增加可选 `versionKey`，过滤在分页切片之前执行；空 `projectVersion` 映射到 `workspace`。同名标签归入同一摘要，时间顺序仍由记录自身决定。

渲染进程按项目请求一次版本摘要，并把 `changeIds` 映射到 Change 行与详情。没有历史依据的 Change 显示“尚无版本活动”，不自动绑定当前版本。

### 7. 版本控件是标题上下文，不是新的页面

项目标题区新增带标签图标的紧凑触发器，展示有效标签或“当前工作区”；Dropdown Menu 展示来源、刷新、自动/手动状态和“项目设置”。完整编辑仍放在 Radix Dialog 中，以分段控件选择模式，并对手动输入做就地校验。

活动按时间排序，并在版本上下文变化处插入轻量分组标题。活动和修订工具栏使用同一版本筛选器。Change 行只显示最近关联版本；跨版本时显示“跨 N 个版本”，详情中可展开完整版本集合。页面区块保持无边框或细分隔线，不在卡片内再嵌套卡片。

### 8. 动效使用 CSS 令牌与 Radix 状态，不增加运行时库

在样式根定义：

- `--motion-press: 120ms`
- `--motion-fast: 160ms`
- `--motion-standard: 200ms`
- `--motion-overlay: 240ms`
- `--ease-out-ui: cubic-bezier(0.23, 1, 0.32, 1)`
- `--ease-in-out-ui: cubic-bezier(0.77, 0, 0.175, 1)`

按压元素使用约 `scale(0.97)`，只在精确指针环境启用悬停位移。Dropdown Menu 使用 Radix 提供的变换原点变量；Dialog 保持中心原点。进入以 ease-out，屏幕内指示器移动以 ease-in-out，退出更快。高频键盘触发不等待动画。

预定动画使用 CSS transition 和 Radix `data-state`，不使用 React 定时挂载或 JS 逐帧动画。进度条从宽度过渡改为固定轨道内的 `scaleX`；内容切换主要改变透明度与轻微位移，固定网格轨道和控件尺寸防止布局变化。避免 `transition: all`、`scale(0)`、长于 300ms 的普通 UI 动画和无意义循环。

### 9. 透明材质和动态偏好集中降级

玻璃只保留在侧栏、顶栏、工具栏、菜单和对话框，正文使用稳定实色。现有 `@supports` 规则继续提供无模糊回退，并补充：

- `prefers-reduced-motion: reduce`：取消空间位移/缩放，保留极短颜色或透明度反馈。
- `prefers-reduced-transparency: reduce`：把玻璃表面切换为高对比不透明背景。
- `prefers-contrast: more`：提高边框、焦点环和次要文字对比。

所有浮层继续由 Radix 管理焦点、Escape、方向键和焦点返回；动态保存结果使用可感知文本/实时区域，而不是只靠动画。

## Risks / Trade-offs（风险与权衡）

- [系统未安装 Git 或仓库命令较慢] → `execFile` 设置短超时、输出上限和无 shell 参数，任何失败立即退回 `package.json` 或当前工作区。
- [目录 schema 升级可能影响旧版本回退] → 迁移前保留明确 v1 备份，迁移测试覆盖真实 v1 样本，并在发布说明注明恢复路径。
- [同名标签在不同时间被重复使用] → 摘要按标签合并但记录保留时间；这是版本名称本身的语义，应用不猜测额外身份。
- [历史数量达到保留上限时聚合成本增加] → 当前每项目活动最多 10000、每文档修订最多 500，内存单次线性聚合可接受；查询结果按 React Query 缓存并在历史事件后失效。
- [自动版本不是实时监听 Git] → 在所有明确生命周期事件刷新，并提供标题区单击刷新；避免复杂 Git 内部监听。
- [动效影响高频工作效率] → 时长上限 300ms、退出更快、CSS 可中断、高频键盘操作无阻塞动效，并提供减少动态效果模式。
- [背景模糊在低性能设备上代价较高] → 限制玻璃层面积与叠加层数，正文实色，提供无模糊与减少透明度回退。

## Migration Plan（迁移计划）

1. 扩展共享 schema 与目录加载器，先用夹具验证 v1→v2 后再接入任何写路径。
2. 应用启动读取 v1 时创建备份、迁移并原子保存 v2；已有历史索引不改写。
3. 初始化自动项目的版本解析，再启动项目监听，使首次新记录使用解析后的有效上下文。
4. 接入版本刷新、WatcherManager 上下文替换、历史摘要和筛选 API。
5. 接入渲染界面和 CSS 动效，完成减少动态效果、透明度回退与最小窗口检查。
6. 回滚时可关闭新版本并将备份目录文件恢复为 `catalog.json`；项目文件和历史快照从未被修改。

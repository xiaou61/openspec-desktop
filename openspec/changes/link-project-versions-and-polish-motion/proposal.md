## Why（为什么）

当前“版本”只是一个默认留空的手填字符串：Codex 导入和直接添加项目后通常显示“未设置版本”，活动列表还会在每一行重复该文案；同时监听器捕获的是启动时的旧值，后续修改可能无法正确进入新活动与修订。版本信息因此既不可靠，也没有真正帮助用户理解一个 Change 在哪个版本阶段发生。

桌面工作区已经具备项目、Change、活动和修订数据，现在应把版本提升为贯穿这些数据的上下文，并用克制、连贯且可降级的动效帮助用户看清状态变化，而不是只增加视觉装饰。

## What Changes（变更内容）

- 为本地项目建立“版本上下文”：支持自动识别、手动覆盖、恢复自动模式，并明确显示版本来源。
- 自动识别优先采用当前 Git HEAD 的精确标签，其次采用根目录 `package.json` 的有效版本；均不可用时使用“当前工作区”语义，不制造虚假版本号。
- 新增或导入项目时自动生成版本上下文；重新扫描或用户主动刷新时更新自动上下文，手动设置不会被覆盖。
- 修正监听器中的旧版本捕获问题，保证版本切换后的新活动和新修订使用最新上下文，同时保留历史记录原有版本归属。
- 在项目标题区提供紧凑的版本控件，并把活动与修订按版本聚合、筛选；Change 展示其最近关联版本和跨版本情况。
- 删除列表中逐条重复的“未设置版本”，无明确版本的历史统一归入“当前工作区”。
- 精修工作区动效与反馈：按压反馈、弹窗/菜单进入退出、标签指示器、列表状态切换、进度变化和轻量内容过渡均采用短时、可中断、稳定布局的动画。
- 为减少动态效果、减少透明度以及不支持背景模糊的环境提供完整降级，不降低键盘可用性、焦点可见性和文本对比度。
- 应用只读取本地版本线索，不创建或修改 Git 标签、分支、提交、`package.json` 或 OpenSpec 文档。

## Capabilities（能力范围）

### New Capabilities（新增能力）

- `project-version-context`：定义版本自动识别、手动覆盖、最新值传播、历史归属、Change 关联和版本筛选行为。
- `desktop-motion-polish`：定义高频桌面工作区的交互反馈、状态过渡、性能约束与无障碍降级行为。

### Modified Capabilities（修改能力）

无。当前主规格目录尚未归档任何能力，本变更以新增规格描述行为。

## Impact（影响范围）

- 主进程：增加有界、只读的版本探测服务，并在项目注册、Codex 导入、重新定位、重新扫描与设置更新时协调版本上下文。
- 数据契约与持久化：扩展项目版本元数据；兼容已有目录与历史索引，历史活动/修订继续保留写入时的版本快照。
- 监听与历史：确保版本更新即时作用于后续记录；增加版本摘要或筛选所需的只读查询能力。
- 渲染进程：调整项目导航、Change 列表、详情标题、活动、修订和项目设置；继续通过受限 preload API 获取本地数据。
- 样式系统：补充统一动效令牌、触发点感知的浮层过渡、按压反馈、基于 `transform`/`opacity` 的列表与进度动画，以及偏好降级规则。
- 测试：覆盖探测优先级、旧数据兼容、版本切换边界、聚合/筛选、键盘交互和减少动态效果；不增加运行时网络依赖。

## Why

Codex 索引中的根路径既可能是一个 OpenSpec 项目，也可能是包含多个独立代码仓库的工作区容器。当前导入流程把两者视为同一种候选，导致工作区容器被标记为“不是 OpenSpec 项目”，其下真正可导入的项目也无法被发现。

## What Changes

- 在校验 Codex 根路径前区分“直接 OpenSpec 项目”和“多项目工作区”，对后者执行安全、有界的子项目发现。
- 在导入界面以可展开工作区展示已配置 OpenSpec 的子项目、尚未配置 OpenSpec 的代码仓库，以及工作区和可导入项目数量。
- 允许工作区复选框批量选择所有可导入子项目；父目录本身不作为 OpenSpec 项目注册。
- 将成功导入的子项目继续作为独立项目扫描、监控和归档，并复用现有项目分组能力保留其工作区归属。
- 为自动工作区分组记录规范化来源根路径，提供稳定去重，并迁移现有手工分组而不改变其行为。
- 对嵌套发现设置深度、目录、数量、耗时和符号链接边界；发现被截断或部分失败时提供明确的可恢复提示。
- 不自动创建任何 `openspec/` 目录，不合并子项目规格，也不在本次变更中提供跨项目 Change 编排。

## Capabilities

### New Capabilities

- `multi-project-workspaces`: 从 Codex 根路径识别多项目工作区，安全发现和选择其子 OpenSpec 项目，并将导入结果按来源工作区持久分组。

### Modified Capabilities

无。

## Impact

- 共享契约：Codex 发现结果、工作区摘要、候选状态、导入请求与项目分组元数据。
- Electron 主进程：Codex 根路径分类、有界子目录发现、全局路径去重、批量注册和工作区分组复用。
- 本地目录存储：目录状态版本迁移，以及自动工作区分组的来源路径持久化。
- React 渲染进程：导入弹窗的分层列表、展开状态、三态选择、数量摘要和不可导入原因；主侧边栏显示工作区分组来源。
- 测试与分发：文件系统发现样本、目录迁移、控制器部分成功语义、键盘交互和 Windows 桌面视觉验证。
